# Flask CRM 实战教程：从零构建分层客户管理 API

> 面向有 Python 基础、希望理解 Flask 分层结构的学习者。建议边阅读边敲代码，并以测试结果验证理解。

## 1. 学习目标与项目边界

本项目实现轻量客户管理 REST API：新增客户、列表/关键词搜索/分页、详情查询、完整更新和删除。客户包含姓名、手机号、公司，手机号在数据库层面唯一。

完成后应能解释应用工厂、扩展初始化、Model、Service、Blueprint 的职责，并能通过 HTTP 请求验证接口。

**边界说明：**这是教学项目，不是可直接上线的生产级 CRM。当前没有认证授权、租户隔离、软删除、审计日志、数据库迁移、限流或生产部署配置。删除操作为物理删除。

## 2. 环境准备

建议使用 Python 3.10 或更高版本。

```bash
git clone https://github.com/dongruan00/crm-practice.git
cd crm-practice
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Windows PowerShell 激活虚拟环境：

```powershell
.venv\Scripts\Activate.ps1
```

启动应用：

```bash
python app.py
```

默认访问地址为 `http://127.0.0.1:5000`。首次启动会创建 SQLite 数据表。停止服务可按 `Ctrl+C`。

## 3. 项目结构与职责

```text
crm-practice/
├── app.py                 # 应用工厂、扩展初始化、蓝图注册
├── config.py              # 环境变量与默认配置
├── extensions.py          # SQLAlchemy 扩展实例
├── models.py              # Customer 数据模型
├── customer_service.py    # 业务用例与数据库操作
├── routes.py               # HTTP 参数校验、状态码与响应
├── requirements.txt        # 项目依赖
├── tests/
│   ├── conftest.py         # pytest fixtures 和测试应用
│   └── test_customers.py   # 接口测试
└── docs/
    └── 实战教程.md         # 本教程
```

### 一次请求的调用链

```text
HTTP Client
    ↓
routes.py              解析请求、基础校验、映射 HTTP 状态码
    ↓
customer_service.py    执行业务用例、读写数据库
    ↓
models.py              定义 Customer 表结构
    ↓
SQLite                 持久化数据
```

`app.py` 负责组装应用，不承载客户业务。分层的目标是让职责和修改位置清晰，而不是单纯增加文件数量。

## 4. 核心设计逐步理解

### 4.1 应用工厂与扩展初始化

`create_app()` 创建 Flask 实例，加载配置，调用 `db.init_app(app)` 绑定 SQLAlchemy，并注册客户 Blueprint。应用工厂便于测试时传入独立配置。

`extensions.py` 中的 `db = SQLAlchemy()` 先创建扩展对象；`db.init_app(app)` 再将其绑定到具体应用。这种方式避免扩展模块反向导入 `app.py`，降低循环导入风险。

应用启动时调用 `db.create_all()`。它只创建数据库中尚不存在的表，**不会修改已有表结构**。结构变更应使用 Flask-Migrate/Alembic 等迁移方案。

### 4.2 Model：数据结构

`Customer` 映射到 `customers` 表。`id` 是主键；姓名和手机号不可为空；手机号有唯一约束。`to_dict()` 显式控制 API 返回字段，避免直接把 ORM 对象交给 JSON 序列化器。

Service 层会先查询手机号是否已存在，以便返回可读的业务错误；数据库唯一约束仍不可省略，因为并发请求可能同时通过预检查。

### 4.3 Service：业务用例

Service 层不生成 Flask Response，而是负责业务规则和持久化操作。例如：新增前检查手机号、创建 Customer 实例、提交事务；唯一约束冲突时 rollback，再转换为业务错误。

列表查询将关键词条件同时应用于数据查询和总数查询，因此 `total` 是符合筛选条件的总记录数，而不是当前页条数。分页偏移量为 `(page - 1) * per_page`。

### 4.4 Route：HTTP 边界

Route 负责读取 JSON 或 Query 参数、进行基础格式校验、调用 Service，并将结果映射为 HTTP 状态码。

| 状态码 | 含义 |
|---|---|
| 200 | 请求成功 |
| 201 | 资源创建成功 |
| 400 | 参数错误或业务规则冲突 |
| 404 | 客户不存在 |
| 500 | 未预期的数据库错误 |

本项目的 PUT 要求提供姓名和手机号，按完整更新处理。若要支持部分更新，应设计 PATCH，并明确字段缺省、空字符串和 `null` 的语义。

## 5. API 契约

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/customers` | 新增客户 |
| GET | `/api/customers` | 列表；支持 `keyword`、`page`、`per_page` |
| GET | `/api/customers/<id>` | 客户详情 |
| PUT | `/api/customers/<id>` | 完整更新 |
| DELETE | `/api/customers/<id>` | 删除客户 |

成功响应统一为 `{"code":0,"message":"...","data":...}`。错误响应中的 `code` 为对应 HTTP 状态码。JSON 中的 `code` 字段与 HTTP 状态行是两个概念。

## 6. 接口实操

### 6.1 新增客户

```bash
curl -X POST http://127.0.0.1:5000/api/customers \
  -H "Content-Type: application/json" \
  -d '{"name":"张三","phone":"13800000000","company":"示例科技"}'
```

成功应返回 HTTP 201。重复手机号应返回 HTTP 400。

### 6.2 列表、搜索与分页

```bash
curl "http://127.0.0.1:5000/api/customers"
curl "http://127.0.0.1:5000/api/customers?keyword=张三"
curl "http://127.0.0.1:5000/api/customers?page=1&per_page=5"
```

`page` 从 1 开始；`per_page` 最大为 100。关键词会匹配姓名或公司。

### 6.3 详情、更新与删除

```bash
curl http://127.0.0.1:5000/api/customers/1

curl -X PUT http://127.0.0.1:5000/api/customers/1 \
  -H "Content-Type: application/json" \
  -d '{"name":"李四","phone":"13800000000","company":"新公司"}'

curl -X DELETE http://127.0.0.1:5000/api/customers/1
```

请将示例 ID 替换为实际创建返回的 ID。删除后再次查询该 ID，应返回 404。


## 8. 常见问题排查

| 现象 | 排查方向 |
|---|---|
| `ModuleNotFoundError` | 激活虚拟环境；确认在项目根目录运行；检查文件名和导入名 |
| 数据库表不存在 | 确认模型已导入，并在应用上下文中执行 `db.create_all()` |
| 修改模型后表结构没变化 | `create_all()` 不负责迁移；使用迁移工具管理结构变更 |
| 重复手机号触发异常 | 检查数据库唯一约束及 `IntegrityError` 后的 rollback |
| 接口返回 404 | 核对端口、URL 前缀、HTTP 方法和 Blueprint 注册 |
| 分页结果为空 | 检查页码是否从 1 开始、关键词是否匹配、偏移量计算是否正确 |
